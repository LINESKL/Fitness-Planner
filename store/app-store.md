# Публикация в App Store

Пошаговая инструкция для владельца. Требуется Mac с Xcode.

1. **Apple Developer Program** — вступить на developer.apple.com ($99 в год).
2. **Bundle ID.** В Certificates, Identifiers & Profiles создать идентификатор `kz.aliar.fitnessPlanner`
   с включёнными Push Notifications.
3. **Сертификат и профиль.** Создать сертификат Apple Distribution и профиль распространения App Store для
   этого bundle id; установить их в Xcode.
4. **Push-уведомления.** В разделе Keys создать ключ APNs (.p8), затем загрузить его в Firebase Console →
   Project settings → Cloud Messaging → Apple app configuration (с Key ID и Team ID).
5. **App Store Connect → My Apps → New App.** Платформа iOS, название «Fitness Planner», основной язык
   русский, bundle id из пункта 2, SKU любой.
6. **Карточка.** Описание и ключевые слова взять из `listing.md`; категория «Здоровье и фитнес»;
   анкета возрастного рейтинга (ожидаемый рейтинг 4+); ссылка на политику конфиденциальности
   https://lineskl.github.io/Fitness-Planner/privacy-policy.html; контакт поддержки.
7. **App Privacy.** Заполнить те же данные, что в `privacy-policy.md`: email и идентификатор пользователя
   (связаны с пользователем, для функциональности приложения); данные тренировок и замеры тела (то же);
   точная геопозиция (не связана с пользователем, не сохраняется, для поиска залов); идентификатор
   устройства / push-токен; данные о сбоях (Crashlytics). Отслеживания (tracking) нет.
8. **Скриншоты.** 6.7" — 1290×2796 и 6.5" — 1242×2688, не менее одного, до десяти на размер.
9. **Сборка.**
   ```
   flutter build ipa --release --obfuscate --split-debug-info=build/symbols
   ```
   Символы Dart из `build/symbols` загрузить в Crashlytics, как в `tool/release.sh`.
10. **Загрузка.** Через приложение Transporter (файл `build/ios/ipa/*.ipa`) или Xcode Organizer →
    Distribute App → App Store Connect.
11. **TestFlight.** Дождаться обработки сборки, проверить её во внутреннем тестировании на реальном устройстве.
12. **Отправка на ревью.** Выбрать сборку в карточке версии, указать демо-доступ для ревьюера, отправить.

## Типичные причины отказа

- В приложении нет удаления аккаунта — Guideline 5.1.1(v): если можно создать аккаунт, его нужно уметь
  удалить из приложения.
- Нет демо-доступа для ревьюера: указать в заметках для ревью тестовый email и пароль либо подсказать
  «Продолжить как гость».
- Запрос геолокации без понятного пояснения: текст разрешения должен объяснять поиск залов рядом.
- Данные App Privacy не совпадают с политикой конфиденциальности.
- Вход через Google без «Входа через Apple» — Guideline 4.8: при стороннем входе Apple может потребовать
  равноценный вариант (вход по email и паролю в приложении уже есть; при отказе добавить Sign in with Apple).
