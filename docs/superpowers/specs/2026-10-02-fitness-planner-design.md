# Fitness Planner — дизайн

Дата: 2026-10-02
Тема курса: №8 Fitness Planner (индивидуальный проект Flutter, AlmaU)

## Цель

Личный дневник силовых тренировок. Пользователь записывает упражнения, подходы, вес и повторы.
Перед каждым упражнением приложение показывает, что он делал в прошлый раз, и предзаполняет поля.
По истории строится статистика прогресса.

**Критерий успеха:** на тренировке не нужно ничего помнить; прогресс по каждому упражнению виден на графиках.
Автор сам пользуется приложением на iPhone, сдаёт проект на Android.

## Платформы

- **Android** — основная платформа сдачи: Kotlin Platform Channel, подписанный AAB, Google Play internal testing.
- **iOS** — поддерживается с первой недели из того же кода. Установка на личный iPhone через Xcode (бесплатный Apple ID, подпись на 7 дней).
  Push на iOS требует платного Apple Developer ($99/год) и APNs-ключа — до его появления push на iOS не работает, остальное работает.

**Почему Riverpod, а не BLoC:** в приложении много асинхронных данных (история из Hive, синхронизация с Firestore, кэш API).
Riverpod даёт состояния loading/data/error из коробки и закрывает DI без get_it. BLoC потребовал бы event/state/bloc на каждую фичу —
для приложения, построенного вокруг CRUD, это лишний объём. Обоснование попадает в README.

## Архитектура

Код делится по фичам, внутри каждой — три слоя.

```
lib/
  core/            тема, роутер, DI-провайдеры, ошибки, сетевой клиент
  features/
    workout/       журнал: тренировка → упражнения → подходы, таймер отдыха
    exercises/     каталог упражнений (wger + кэш + свои упражнения)
    stats/         графики прогресса, рекорды, «в прошлый раз»
    gyms/          карта залов, метка зала
    auth/          вход и регистрация
    settings/      тема, единицы (кг/фунты), напоминания, инфо об устройстве
    progress/      фото прогресса, шаги за день
      presentation/   экраны, виджеты, Riverpod-контроллеры
      domain/         сущности, интерфейсы репозиториев, use cases
      data/           реализации репозиториев, источники данных, DTO
```

**Правила зависимостей:** `presentation → domain ← data`. `domain` не импортирует Flutter, Hive, Firebase и dio.
Реализации репозиториев подставляются через провайдеры Riverpod в одном месте (`core/di`).

**Offline-first:** все чтения и записи тренировок идут в Hive. Синхронизатор в фоне отправляет локальные изменения в Firestore
и при входе на новом устройстве подтягивает историю. Конфликты решаются по `updatedAt` (побеждает последняя запись).

## Модель данных (domain)

- `Exercise` — `id`, `name`, `muscleGroup`, `imageUrl?`, `source` (`wger` | `custom`).
- `Workout` — `id`, `startedAt`, `finishedAt?`, `gymId?`, `note?`, `exercises: List<WorkoutExercise>`, `updatedAt`.
- `WorkoutExercise` — `exerciseId`, `order`, `sets: List<SetEntry>`.
- `SetEntry` — `weight` (всегда в кг, конвертация в UI), `reps`, `order`, `isWarmup`.
- `Gym` — `id`, `name`, `lat`, `lng`, `source` (`osm` | `custom`).

Firestore: `users/{uid}/workouts/{workoutId}` (упражнения и подходы вложены в документ), `users/{uid}/gyms/{gymId}`,
`users/{uid}/customExercises/{id}`. Security Rules: доступ только к своему `uid`.

## Ключевые сценарии

1. **Запись тренировки.** Пользователь выбирает упражнение и видит «В прошлый раз: 80 кг × 8, 8, 7» — подходы последней
   тренировки с этим упражнением. Поля нового подхода предзаполнены. «Готово» сохраняет подход и запускает таймер отдыха.
2. **Статистика.** По упражнению: график максимального веса и объёма (Σ вес × повторы, без разминочных подходов) по датам;
   личные рекорды (максимальный вес, оценочный 1ПМ по Эпли); количество тренировок в неделю. Фильтр по залу.
3. **Залы.** Карта залов поблизости (Overpass, `leisure=fitness_centre`). Выбранный зал привязывается к тренировке.
   Можно добавить свой зал меткой на карте.
4. **Синхронизация.** Описана в разделе «Offline-first».
5. **Напоминания.** Push через FCM: напоминание о тренировке в выбранные дни.

## Ошибки и пустые состояния

- Нет сети: журнал и статистика работают; каталог упражнений — из кэша; на экране каталога — баннер «офлайн».
- Ошибка API: экран ошибки с кнопкой «Повторить».
- Отказ в геолокации: карта без «рядом со мной», зал выбирается поиском или меткой вручную.
- Пусто: подсказка начать первую тренировку / добавить первое упражнение.

## Нативные возможности

- **Камера:** фото прогресса, хранятся в каталоге приложения, список в Hive.
- **Датчик:** шагомер — шаги за день на главной (Android: Activity Recognition, iOS: CoreMotion).
- **Platform Channel:** `MethodChannel('fitness/device')` — уровень заряда и модель устройства, показ в настройках.
  Реализация на Kotlin (обязательно по курсу) и Swift (для iOS).
- **iOS Info.plist:** `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`, `NSLocationWhenInUseUsageDescription`,
  `NSMotionUsageDescription`.
