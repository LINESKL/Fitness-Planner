# Fitness Planner

[![CI](https://github.com/LINESKL/Fitness-Planner/actions/workflows/ci.yml/badge.svg)](https://github.com/LINESKL/Fitness-Planner/actions/workflows/ci.yml)

Дневник силовых тренировок на Flutter для Android и iOS.

## Цель

На тренировке не нужно помнить, сколько и с каким весом делал в прошлый раз. Приложение записывает
упражнения, подходы, вес и повторы, перед каждым упражнением показывает прошлый результат и строит
графики прогресса.

## Целевая аудитория

Люди, которые регулярно занимаются в тренажёрном зале и хотят видеть свой прогресс: от новичков,
которым важно не забыть рабочие веса, до опытных атлетов, следящих за объёмом и рекордами.

## Аналоги

| Приложение | Что хорошо | Чего не хватает |
|---|---|---|
| Strong | Быстрая запись подходов, прошлые значения рядом | Графики и часть функций платные |
| Hevy | Удобная статистика, синхронизация | Социальная лента, которая не всем нужна |
| FitNotes | Бесплатное, работает офлайн | Только Android, устаревший интерфейс |

Отличие Fitness Planner: офлайн-первый журнал, бесплатная статистика, привязка тренировок к залу на карте.

## Возможности

- **Программа-сплит.** Дни («Грудь + трицепс», «Ноги»…) с упражнениями, числом подходов и диапазоном
  повторов; дни идут по кругу, «Сегодня» подсказывает следующий.
- **Тренировка в фокус-режиме.** На экране один текущий подход: вес и повторы уже подставлены
  из прошлого раза, между подходами — одно нажатие «Готово».
- **Подсказка прогрессии.** Если в прошлый раз выполнены все повторы до верха диапазона — сегодня
  +2.5 кг (для упражнений со своим весом прибавки нет).
- **Таймер отдыха** по времени окончания (верно считает и после сворачивания), вибрация в конце.
- **Тип подхода и RPE**: разминка, до отказа, дроп-сет; тяжесть 6–10.
- **Заметки к упражнениям** — показываются каждый раз на этом упражнении.
- **Личные рекорды** (оценочный 1ПМ по Эпли) — объявляются сразу после подхода.
- **Итоги тренировки**: длительность, объём, подходы, рекорды, сравнение с прошлым разом этого дня.
- **Прогресс**: календарь тренировок, серия недель, подходы по группам мышц за неделю (ориентир 10–20),
  таблица рекордов, вес тела и замеры с графиком.
- **Карточка упражнения**: график 1ПМ / лучшего веса / объёма, лучший подход, история.
- **Каталог**: встроенные упражнения на русском, ~900 упражнений wger, свои упражнения.
- **Офлайн**: всё хранится локально; идущая тренировка переживает перезапуск приложения.
- **«Загрузить пример»** в настройках — программа и месяц истории для показа.

## Как устроена тренировка

```
Сегодня → «Начать тренировку» (день программы)
   │
   ▼
Подход N из M ── «Готово» ──► Отдых (таймер, ±15 с) ──► Подход N+1 …
   │                                                   │
   └── «План»: перейти / переставить / добавить / заменить упражнение
                                                       ▼
                         Все подходы сделаны → «Завершить тренировку» → Итоги
```

Состояние — неизменяемый `ActiveWorkout` (`lib/features/workout/domain/active_workout.dart`) с курсором
`(упражнение, подход)` и фазой `set | rest | finished`; каждое действие возвращает новую копию и
сохраняется в Hive.

## Экраны

1. Вход
2. Сегодня — день по плану, неделя и серия, объём, свежий рекорд
3. Программа — дни сплита; редактор дня
4. Тренировка — подход, отдых, конец; план тренировки
5. Итоги тренировки
6. Прогресс — обзор (календарь, мышцы, вес), рекорды, тело; детали тренировки; новый замер
7. Упражнения — каталог с поиском; карточка упражнения; своё упражнение
8. Настройки — тема, отдых, пример данных

## Архитектура

Код разделён по фичам (`lib/features/<фича>/`), внутри каждой — три слоя:

- `domain/` — сущности (`SetEntry`, `ExerciseLog`, `ActiveWorkout`, `Exercise`) и интерфейсы репозиториев
  (`WorkoutRepository`, `ExerciseRepository`). Чистый Dart, без Flutter и пакетов.
- `data/` — реализации репозиториев (сейчас в памяти, дальше — сеть и Hive).
- `presentation/` — экраны, виджеты и провайдеры Riverpod.

Зависимости направлены внутрь: `presentation → domain ← data`. Реализации подставляются в одном месте —
провайдеры `workoutRepositoryProvider` и `exerciseRepositoryProvider` (Dependency Injection); в тестах их
заменяют фейками через `overrides`.

### Почему Riverpod, а не BLoC

- В приложении много асинхронных данных (история, каталог из сети, кэш). `AsyncNotifier` и `FutureProvider`
  дают состояния загрузки, ошибки и данных без собственных классов состояний.
- Riverpod одновременно решает Dependency Injection — отдельный `get_it` не нужен.
- Провайдеры не зависят от `BuildContext`: логику можно проверить в unit-тесте через `ProviderContainer`.
- BLoC потребовал бы событие, состояние и блок на каждую фичу; для приложения, построенного вокруг
  записи и чтения данных, это лишний объём.

Provider (пакет) остаётся для базового сценария — настроек приложения.

## Источник данных

Каталог упражнений — открытый REST API [wger.de](https://wger.de/api/v2/) (`GET /exerciseinfo/`, без ключа).
Запросы — через `dio` с таймаутами (10 с на соединение, 30 с на ответ), модели ответа — `freezed` +
`json_serializable`. В API почти нет русских переводов и нет поиска по названию, поэтому каталог =
встроенные русские упражнения + упражнения wger (русское имя, если есть, иначе английское), а поиск
выполняется на устройстве с задержкой 300 мс после ввода. Экран обрабатывает состояния загрузки,
ошибки (с повтором), пустого результата и обновление жестом pull-to-refresh.

Генерация моделей: `dart run build_runner build -d`.

## Локальное хранение и офлайн

- **Hive** (`hive_ce`): история тренировок (бокс `workouts`) и кэш каталога упражнений (бокс `exercise_cache`).
- **SharedPreferences**: настройки — тема (системная, светлая, тёмная) и длительность отдыха между подходами.
- **Offline-first**: запись и просмотр тренировок работают без сети, потому что всё хранится локально.
  Каталог при каждом успешном запросе сохраняется; если сети нет, показывается сохранённая копия
  с пометкой «Нет сети», а если копии ещё нет — ошибка с кнопкой «Повторить».

## Навигация и адаптивность

GoRouter (`lib/core/router.dart`), у всех маршрутов есть имена:

| Маршрут | Экран |
|---|---|
| `/login` | Вход |
| `/` | Сегодня (вкладка) |
| `/settings` | Настройки |
| `/program`, `/program/:templateId` | Программа (вкладка), редактор дня |
| `/progress` | Прогресс (вкладка) |
| `/progress/workout/:workoutId` | Детали тренировки |
| `/progress/body/new` | Новый замер |
| `/exercises`, `/exercises/:id` | Каталог (вкладка), карточка упражнения |
| `/exercises/edit/:id` | Своё упражнение |
| `/workout`, `/workout/plan` | Идущая тренировка, её план |
| `/summary/:workoutId` | Итоги тренировки |

- Вкладки — `StatefulShellRoute.indexedStack`: у каждой свой стек, позиция сохраняется при переключении.
- Защита маршрутов: `redirect` пускает без входа только на `/login`, после входа уводит на главную;
  `refreshListenable` пересчитывает маршрут при входе и выходе. Пока вход — «как гость» (флаг в
  SharedPreferences); на неделе 8 его заменит Firebase Authentication за тем же интерфейсом `AuthRepository`.
- Адаптивность: от 600 пикселей ширины (планшет, альбомная ориентация телефона) нижняя панель
  заменяется боковой `NavigationRail`, а ширина контента ограничивается 720 пикселями.

## Управление состоянием: setState, InheritedWidget, Provider

Ключевая функция — запись тренировки (правка веса и повторов, добавление подходов и упражнений,
сохранение в историю) — была реализована тремя способами подряд.

| Подход | Как устроено в проекте | Плюсы | Минусы | Когда применять |
|---|---|---|---|---|
| `setState` | Тренировка жила в `State` экрана, история — в `HomeShell`, передавалась параметрами и колбэком `onFinish` | Ноль зависимостей, всё видно в одном файле | Проброс данных через несколько уровней; тренировка терялась при закрытии экрана | Локальное состояние одного виджета: галочка, поле ввода, анимация |
| `InheritedWidget` (`InheritedNotifier`) | `WorkoutStore` (`ChangeNotifier`) над `MaterialApp`, доступ через `WorkoutScope.of(context)` | Встроено во Flutter, нет проброса параметров, перестраиваются только зависимые виджеты | Шаблонный код (`of`, `updateShouldNotify`), нет разделения «читать» и «подписаться» | Небольшие общие данные без сторонних пакетов: тема, локаль |
| Provider | `ChangeNotifierProvider<WorkoutStore>`, `context.watch` в `build`, `context.read` в обработчиках | Меньше кода, явное разделение `watch`/`read`, удобная подмена в тестах (`.value`) | Зависимость от `BuildContext`, ошибки поиска провайдера видны только при запуске | Простые общие состояния среднего размера |

Итог: модель тренировки (`ActiveWorkout`) — неизменяемая и не зависит от способа хранения, поэтому
переход между подходами затронул только слой представления.

## Нативные функции

- **Камера** — фото прогресса к замеру тела (`image_picker`): снимок с камеры или из галереи копируется в папку
  приложения (`path_provider`), в списке замеров — миниатюра, по нажатию — на весь экран с увеличением.
  Удалили замер — удаляется и файл. Камера недоступна — сообщение, замер сохраняется без фото.
- **Свой Platform Channel** `kz.aliar.fitness_planner/device` — Kotlin в
  `android/app/src/main/kotlin/kz/aliar/fitness_planner/MainActivity.kt`, Dart в `lib/core/device_channel.dart`:
  - `keepScreenOn(bool)` — во время тренировки экран не гаснет между подходами (`FLAG_KEEP_SCREEN_ON`);
  - `batteryLevel()` — заряд из `BatteryManager`; меньше 15% при старте тренировки — предупреждение.
  На iOS нативной стороны нет — методы тихо ничего не делают.
- Проверка на устройстве: `flutter test integration_test/device_channel_test.dart` — ответ приходит из Kotlin.

## Производительность

- Каталог wger грузится страницами по 50 (`limit/offset`) с бесконечной прокруткой: когда последняя строка
  списка появляется на экране, подгружается следующая страница. Раньше весь каталог (932 упражнения, 6.4 МБ JSON)
  приходил одним запросом. Поиск — по загруженным страницам; если ничего не нашлось, страницы подгружаются дальше.
- Картинки — `cached_network_image`: кэш на диске (видны без сети, не качаются заново), в памяти — уменьшенные.
- Таймер отдыха перерисовывает только цифры, а не весь экран отдыха.
- Линтеры `prefer_const_*` включены — `const` проверяется при каждом `flutter analyze`.

Замер — `integration_test/catalog_perf_test.dart` (профильный режим, эмулятор): открыть каталог и пролистать.

```bash
flutter drive --profile --no-dds --driver=test_driver/perf_driver.dart \
  --target=integration_test/catalog_perf_test.dart
```

| | Каталог готов | Кадров не уложились в 16 мс (растеризация) | Растеризация, p90 |
|---|---|---|---|
| До: весь каталог одним запросом | 1.9–2.7 с | 23–36 | 16–17 мс |
| После: страницы, первый запуск | 1.3–1.9 с | 7–36 | 5–21 мс |
| После: страницы, картинки уже в кэше | 1.3 с | 4 | 5.6 мс |

При первом запуске `cached_network_image` инициализирует дисковый кэш — один кадр сборки ~50 мс;
дальше картинки берутся с диска, и прокрутка почти не теряет кадров.

## CI

GitHub Actions (`.github/workflows/ci.yml`) на каждый push в `main` и pull request: `flutter pub get` →
`dart format` → `flutter analyze` → `flutter test --coverage` → `flutter build apk --release`.
APK и отчёт покрытия (`lcov.info`) публикуются как артефакты запуска, процент покрытия — в сводке запуска.
Integration-тест на Android-эмуляторе — отдельный job, запускается вручную (Actions → CI → Run workflow).

## Тесты

- Unit-тесты бизнес-логики: правила прогрессии, рекордов, статистики, модель идущей тренировки.
- Репозитории и провайдеры с моками `mocktail` (`cached_exercise_repository_test.dart`, `workouts_notifier_test.dart`),
  хранилища Hive — на временной папке.
- Widget-тесты всех экранов и сценариев.
- Integration-тест сквозного сценария (`integration_test/workout_flow_test.dart`): вход гостем → тренировка
  по дню программы → итоги → тренировка в «Прогрессе».

```bash
flutter test --coverage                        # unit + widget, отчёт в coverage/lcov.info
flutter test integration_test -d emulator-5554 # на эмуляторе или телефоне
```

## Структура репозитория

- `lib/core/` — тема, роутер, форматирование, общие виджеты
- `lib/features/<фича>/` — `home` (Сегодня), `program`, `workout`, `progress`, `exercises`, `settings`, `auth`;
  внутри — `domain` / `data` / `presentation`
- `test/` — unit- и widget-тесты (зеркалят `lib/`)
- `lib/features/workout/domain/` — в том числе задачи недели 1 на Dart (null safety, классы, коллекции, async/await),
  написанные сразу как доменная логика приложения; тесты — в `test/features/workout/domain/`
